# ADR 0006: Defaults for telemetry, multimodal, experiments and decay (#91 #92 #96 #97 #98)

Status: Accepted by owner delegation (2026-11-01). Register: #83.

## Decisions
1. **GA4 revenue** comes from the GA4 Data API command `google_analytics_revenue` (organic search `totalRevenue` per landing page, currency as reported by GA4) or from the user's CSV export. Currency is never guessed. A page missing from the data is unknown, not zero. Needs a connected Google account and purchase events in GA4; the command is tested against fixture responses only.
2. **Crawl Efficiency Matrix** thresholds (`wasteMaxTrs` 45, `wasteMinHits` 25, `starvationMaxHits` 2) are confirmed on labelled fixtures (`matrixCalibration.ts`). Real logs need the user's own labels; every value stays overridable.
3. **Images**: native Rust download (public hosts, raster only, 5 MB, no cookies) with CORS fetch as fallback. pHash default 8 of 64 bits is confirmed on seeded synthetic fixtures (`phashCalibration.ts`), still adjustable 0-16.
4. **OCR, CLIP, ASR**: OCR runs only through a local Ollama vision model the user names; results stay partial (whole-image box, no confidence). Text-image alignment is a deterministic lexical heuristic (ALT, file name, page text) with confidence null. Transcripts come from WebVTT/SRT captions; no speech-to-text model is bundled or downloaded.
5. **Experiments**: the counterfactual adds a seasonal structural model (local level plus weekly seasonality, seeded posterior-predictive simulation). It is a BSTS-style approximation, not a full Bayesian fit. Page-level interventions use per-page daily GSC series saved per project; a control page may share links or templates with the changed page, and the UI says so. The outcome is chosen per project: Search Console clicks (default), GA4 key events or GA4 revenue of organic search sessions (`google_analytics_daily`, daily, per site or per landing page, currency as GA4 reports it). The site-wide GA4 series is estimated without a control (every page is part of it); a page uses other saved page series of the same outcome as control. The PDF evidence table names the outcome.
6. **Decay Radar**: an optional Ollama embedding of the market vocabulary gives a neural centroid labelled with the model name. Without a configured model the lexical centroid stays. Native scheduled handoffs carry a SHA-256 delivery fingerprint; the WebView handles a fingerprint once. The scheduler owns monitoring-alert delivery state: `scheduled_worker::ledger` (`reserve_monitoring_alert`, `finish_monitoring_alert`, `list_monitoring_ledger`) decides duplicates by fingerprint and frequency window, holds in-flight reservations and records deliveries per project. The TypeScript dispatch (`deliverMonitoringAlert`) is a thin consumer: native decides in the desktop app, the local history is the mirror shown in settings, and the local ledger decides if the native call fails or in a browser. Alert evaluation (comparing runs) stays in TypeScript because the comparison inputs live there.
7. **PDF**: one evidence section (revenue, experiment estimates, SERP drift) is part of the crawl report template and appears only with saved data.

## Consequences
No ML model is mandatory or downloaded. All thresholds are visible defaults with a documented origin, not claims about real-world accuracy.
